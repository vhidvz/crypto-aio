## 2. Rulings P25-R1–P25-R25

Each line gives the decision, then the cost if it is wrong.

- **P25-R1.** Every subagent on opus, at most about 4 at once; proof or transport changes run their suites 30 times; the pre-flight minor N1 (a caller-aborted identity check never counts as a miss) folded into Task 3. Cost: none.
- **P25-R2.** Local merges of finished plans into `main` proceed without asking once the final review is clean and the merged result verifies; never push or touch remotes without an explicit request. Cost: none (reversible).
- **P25-R3.** `eslint.config.mjs` ignores `.superpowers/**` (controller commit `ddb38d1`), so scratch copies in any worktree never break lint. Cost: none.
- **P25-R4.** `exactIntegers` revives only literals of at most 80 digits (u256 is 78); a longer one is a retryable `PROVIDER_UNAVAILABLE`. A hostile 2 MB literal now costs about 3 ms instead of 312 ms. Cost: none.
- **P25-R5.** Probes take the next bucket token ahead of queued requests (beyond the brief: the brief's code still starved a height probe). Cost: a probe can delay one queued request by one token.
- **P25-R6, R7.** A fully failed refresh backs off at least `(probe calls + 1) ÷ rps` (the `+1` measured and pinned); the `rpc.error` latency change is in the CHANGELOG; priority takers wake in order but are not a queue. Cost: one extra token interval of backoff on slow buckets.
- **P25-R8.** The proof quorum size counts every endpoint not proven mismatched (verified, unchecked or identity-throttled); identity failures feed the same miss counter. Cost: proofs decide nothing longer at startup or during identity outages.
- **P25-R9.** Breaker-open endpoints also count toward the size; they never serve. Cost: proofs decide nothing while an honest breaker is open.
- **P25-R10.** Refresh re-probes identity when no height probe exists; with no probes at all the R8/R9 counting does not apply (families must set probes, R19); at most one miss per `healthIntervalMs`; sizing keyed on `quorum === 'proof'` whatever the purpose; a definitive RPC error decides a proof quorum only when the required number of endpoints return an equivalent one (same `rpcCode`), else `PROVIDER_INCONSISTENT`. Five EVM driver tests now expect `PROVIDER_INCONSISTENT` where one endpoint errs and another answers. Cost: more retries (liveness only).
- **P25-R11.** R8/R9 counting applies only when a height probe exists or identity is probed. Cost: none.
- **P25-R12.** `signaturesFrom` docs and tests: the core answers `SIGNATURE_MISMATCH` when a driver does not compare the payload; a driver that does compare answers `INVALID_INTENT`. Cost: none.
- **P25-R13.** A variant rejects symbol keys; an empty variant is absent; `undefined` values are `INVALID_ADDRESS`; the codec contract is documented (JSON scalars, semantic fields only). Cost: none.
- **P25-R14.** The accepted-rebroadcast path clears a stale reason; a store patch key set to `undefined` means absent. **One new store-contract assertion:** observation-side undefined keys read back `undefined`, never `null`. Cost: durable stores that wrote `null` fail the contract suite (intended).
- **P25-R15.** One shared `pendingAfterSend` helper for accept and `recordAmbiguous` (refused, dropped or missing to pending, reason cleared); a proven `replaced` clears the reason on both paths. Cost: none.
- **P25-R16.** AttemptRef guard docs and tests: the `NONCE_CONFLICT` row also covers `submitSignatures` and awaiting-signature; the `leaseMs` append bound is documented for durable stores. Cost: none.
- **P25-R17.** `samePlugin` compares enumerable own symbol keys, non-enumerable keys and array holes as `util.isDeepStrictEqual` does; `samePlugin(fakePlugin(), fakePlugin())` is pinned. Cost: none.
- **P25-R18.** A20 docs scoped to the ten Bitcoin SLIP-0132 versions; secrecy asserted through `JSON.stringify` and `cause`; a mainnet UTXO case added. Cost: none.
- **P25-R19.** A caller's `hd` never reaches a driver (`addressFromPublicKey` strips it; `deriveAddress` goes through the core-built options); every extended-key refusal is fixed text with no `cause`; a falsy `xpub` means no `hd`, a truthy non-string is `CONFIG_INVALID`; `hd.xpubVersions` copies only `private` and `public`. - **P25-R22.** The trial-request rule. On a proof-quorum read, an out-of-count endpoint with a half-open breaker is also asked. It can only block: disagreement or refusal gives `PROVIDER_INCONSISTENT`, and a transport failure is ignored. Only in-count endpoints answer toward the quorum. One trial per read, chosen by lowest priority, then name. Cost: one extra request per proof read while an endpoint recovers.

## 3. Binding notes for Plans 3–6 (from the board; apply at execution)

- **Transport (Task 1, Plans 4 and 5).** Under `exactIntegers` a u64 field may be a `number` or a `bigint`: convert with `BigInt(value)`. Quorum keys must not `JSON.stringify` their input (a `bigint` throws, which counts as a disagreement); use the core's canonical JSON or explicit field picks. `rpcData` writes big integers as decimal strings.
- **Rate limits (Task 2, Plans 3–6).** Set `rateLimit` on keyless presets (toncenter `{ rps: 1 }`, or `0.5` each for v2 and v3, X2). Each probe call costs a token and goes ahead of queued requests, so keep probes to one call on low tiers, and keep `rps × healthIntervalMs` well above the probe calls per refresh. FakeClock tests must drive the clock: the first request on a 1 rps endpoint takes at least 1 s.
- **Proofs (Task 3, Plans 3–6).** Always set a height probe and an identity probe with `expectedIdentity` (R19). Proof paths treat `PROVIDER_UNAVAILABLE` and `PROVIDER_INCONSISTENT` as "decide nothing" (lesson 18). Two endpoints make the lag filter inert: anchor proof reads to a height (lesson 17), and recommend three or more endpoints. `status().lagging` is measured against the best height, not the corroborated one. Proofs wait at startup, while an honest breaker is open (at least `openMs`), and about 3 health intervals after an endpoint dies.
- **Signed payloads (Task 4, Plan 3).** `signaturesFrom` is synchronous and I/O-free, and throws a fixed-text `ValidationError('INVALID_INTENT')` when the payload is not the prepared transaction. Keep one signed-payload paragraph in the guides (X3).
- **Variants (Task 5, Plans 3, 4, 6).** A variant is part of the intent hash: JSON scalars and semantic fields only. TON puts only `bounceable` there, never `urlSafe` or `testOnly`. UTXO `{ type }` and Tron `{ hex }` are hashed; keep them deterministic.
- **Plugins (Task 8, every family, X6).** Build every plugin function once at module level and pin `samePlugin(xPlugin(), xPlugin())`.
- **xpub (Tasks 9 and 10, Plan 3).** Task 8 Step 4b reads `wallet.hd as WalletHdOptions | undefined` (`WalletOptions` stays a plain record, X7) and calls `deriveXpubChild(hd.xpub, path, hd.xpubVersions, { testnet })` (X4); the three-argument call compiles and skips the class check. `hd.xpub` is always public. `options.hd` is reserved. A test fixture with a placeholder `xpub` now fails at wallet resolution.
- **Refusals and trials (P25-R21–R23).**
  - Two refusals agree under a proof quorum only on the same code, HTTP status and `rpcCode`. The message counts only for -32000..-32099 and -32603, and REST bodies are never compared. Never decide a proof from one endpoint's error text.
  - A recovering endpoint may add one trial request per proof read, and a read waits for a trial it sent.
  - Proof endpoints want `burst ≥ 2`.
- **Proof tests (A14/A24).** A lagging proof endpoint must stay within `maxLagBlocks`, or the test adds a second endpoint at the head; a proof with a failing height probe decides nothing until 3 refreshes fail.
